# 躬行启杭网站测试清单与上线标准

## 1. 文档用途

本文件是项目进行功能验收、阶段性回归、发布前检查和部署后冒烟测试时的统一依据。

测试状态使用：

- `[ ]`：尚未测试
- `[x]`：测试通过
- `[!]`：存在问题，但经评估不阻塞上线
- `[X]`：测试失败，阻塞上线
- `[-]`：当前版本不包含该功能

测试分为四层：

1. 每次修改后，由修改代码的对话执行针对性检查。
2. 一个功能完成后，在功能分支合并前执行功能验收。
3. 准备发布时，按照本文件执行完整回归测试。
4. 部署完成后，执行线上冒烟测试。

每次准备修改时，修改对话应先判断“这项修改最可能破坏什么”，用判断结果确定本次针对性测试范围。这项判断不要求每次都执行完整测试清单。

## 16. 问题等级

### P0：绝对禁止上线

- 密钥或管理员密码泄露
- 普通用户可以执行管理员操作
- 数据库或上传文件会丢失
- 网站无法启动或核心数据损坏

### P1：修复后才能上线

- 核心页面打不开
- 留言、问答或管理员审核等核心流程失败
- 文件上传或访问完全不可用
- 生产环境仍访问 `localhost`
- HTTPS、域名或后端服务不稳定

### P2：可以评估后上线

- 个别非核心页面体验问题
- 部分错误提示不够清楚
- 特定手机尺寸存在轻微布局问题
- 非核心功能偶发失败但有替代方案

### P3：可以后续修复

- 轻微文案或样式问题
- 不影响使用的小动画问题
- 非核心视觉细节

## 17. V1 上线标准

只有同时满足以下条件，才可以判定为“允许上线”：

- [ ] P0 问题为 0
- [ ] P1 问题为 0
- [ ] 所有计划上线的核心业务流程通过
- [ ] 前端 build 和 lint 通过
- [ ] 后端语法检查、启动和健康检查通过
- [ ] 生产构建不包含 `localhost` 或真实密钥
- [ ] 管理员、上传、删除和审核接口完成服务端鉴权
- [ ] `.env`、数据库和用户文件不进入 Git
- [ ] 数据重启后仍存在
- [ ] 已完成数据库备份和恢复测试
- [ ] 手机端和桌面端均可完成核心操作
- [ ] HTTPS 和正式域名正常

最终结论只能选择一种：

- `允许上线`
- `有条件上线：列出已接受的 P2 问题`
- `禁止上线：列出 P0/P1 阻塞问题`
