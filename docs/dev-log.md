## 2026-07-27：明确 Codex 对话与 Git 分支协作规则

### 实现内容

- 在项目 `AGENTS.md` 中增加对话、分支、worktree 和任务交接规则。
- 明确同一工作目录同时只能由一个对话修改代码。
- 明确小改动可以直接推进 `main`，涉及接口、数据、安全、依赖、存储或部署的改动应使用功能分支。
- 增加“新改动开始时只判断一次大小”的规则；同一改动执行期间不重复判断，除非需求范围发生实质扩大。

### 设计原因

- 多个 Codex 对话共享同一工作目录，普通 Git 分支不能隔离同时发生的文件修改。
- 用风险而不是对话数量决定是否创建分支，可以在保持简单工作流的同时保护稳定主线。
- 真正并行修改必须使用独立 worktree，并继续协调共享接口和高冲突文件。
- 改动大小判断属于当前对话的固定起始检查，无需额外创建 subagent。

### 验证结果

- 本轮只修改规则和开发日志，没有改变前端、后端或数据行为。
- 已检查新增规则与现有开发、验证和安全要求没有冲突。

### 遗留问题与下一步

- 仓库仍需要完成首次提交和远程推送。
- 当前只有一个工作目录，后续仍按“一次一个代码修改对话”执行。
