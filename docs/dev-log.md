## 2026-07-27：明确 Codex 对话与 Git 分支协作规则

### 实现内容

- 在项目 `AGENTS.md` 中增加对话、分支、worktree 和任务交接规则。
- 明确同一工作目录同时只能由一个对话修改代码。
- 明确小改动可以直接推进 `main`，涉及接口、数据、安全、依赖、存储或部署的改动应使用功能分支。
- 增加“新改动开始时只判断一次大小”的规则；同一改动执行期间不重复判断，除非需求范围发生实质扩大。

### 设计原因

- 多个 Codex 对话共享同一工作目录，普通 Git 分支不能隔离同时发生的文件修改。
- 用风险而不是对话数量决定是否创建分支，可以在保持简单工作流的同时保护稳定主线。
- 真正并行修改必须使用独立 worktree，并继续协调共享接口和高冲突文件。
- 改动大小判断属于当前对话的固定起始检查，无需额外创建 subagent。

### 验证结果

- 本轮只修改规则和开发日志，没有改变前端、后端或数据行为。
- 已检查新增规则与现有开发、验证和安全要求没有冲突。

### 遗留问题与下一步

- 仓库仍需要完成首次提交和远程推送。
- 当前只有一个工作目录，后续仍按“一次一个代码修改对话”执行。

## 2026-07-27：统一前端 API 与文件地址

### 实现内容

- 新增前端运行配置模块，集中管理 API 根地址、文件根地址和课件文件 URL。
- 默认使用同域 `/api` 与 `/data`，同时支持通过 Vite 环境变量配置独立域名。
- 将 Home、Contact、Guestbook、QandA、AITest、Admin、Courseware 的请求地址切换到统一配置。
- 统一 PDF 预览和 PPT 下载地址，兼容 Windows、Linux 和完整 HTTP URL。
- 将 Vite 本地代理目标改为环境可配置，并补充前端环境变量示例。
- 清理 build 暴露出的未使用导入、状态和重复请求，不改变现有页面行为。

### 设计原因

- 避免生产构建继续请求访问者电脑上的 `localhost:8000`。
- 同域默认值适合后续使用 Nginx 反向代理，也保留前后端分离和对象存储独立域名的配置能力。
- 地址规则集中在一个模块，后续切换服务器或存储服务时无需逐页修改。

### 技术与配置

- 使用 React、TypeScript、Vite 的 `import.meta.env` 和 `loadEnv`，未增加第三方依赖。
- 新增 `VITE_API_BASE_URL`、`VITE_FILE_BASE_URL` 和 `DEV_PROXY_TARGET` 配置。
- HTTP API 的请求方法、参数和响应结构均未改变。

### 验证结果

- 使用现有 `package-lock.json` 执行 `npm ci`，未升级或修改锁定依赖。
- `npm run build` 通过。
- `npm run lint` 通过。
- 使用示例独立 API 与文件域名构建成功，产物包含对应配置。
- 恢复默认同域配置后重新构建，最终产物不含本机或测试后端地址。
- 前端源码中不再存在页面级 API 常量或写死的 `localhost:8000`。
