## 2026-07-28：文件存储与数据暴露安全闭环

### 实现内容

- 移除整个 `data/` 的静态目录挂载，改用 `GET /data/uploads/{filename}` 专用文件响应接口。
- 下载接口只接受安全 basename 和 PDF、PPT、PPTX；真实路径必须位于上传目录，符号链接会被拒绝。
- PDF 使用 inline 响应，PPT/PPTX 使用 attachment，文件响应统一包含 `X-Content-Type-Options: nosniff`。
- 上传文件使用服务端 UUID 文件名、1 MiB 分块写入、非公开临时文件和原子移动。
- 增加扩展名、声明 MIME 和内容三重校验；PPT 使用 `olefile`，PPTX 检查 OOXML 结构、ZIP 条目数、目标 XML 与总解压大小。
- 新增 `COURSEWARE_MAX_UPLOAD_MB`，默认 50 MB、允许 1～500；Content-Length 只用于提前拒绝，真实限制仍由流式计数完成。
- 数据库新记录只保存安全文件名；Windows 和 POSIX 历史绝对路径仅在明确以 `data/uploads` 结尾时重映射到当前上传目录。

## 2026-07-29：CORS、可信 Origin 与 CSRF 防护闭环

### 实现内容

- 将全通配 CORS 改为环境变量控制的精确白名单；正式同域部署可完全关闭 CORS。
- 所有环境必须显式配置 `TRUSTED_ORIGINS`；production 只接受 HTTPS 正式来源，development 只接受明确的回环来源。
- 从 ASGI 原始请求头验证 Origin 和 Referer，拒绝重复、逗号拼接、`null` 和不可信来源；Origin 存在但错误时不回退 Referer。
- 管理员会话新增独立随机 CSRF Token，并从 dataclass 默认表示中隐藏。
- 登录和会话检查向前端返回 CSRF Token；前端只在模块运行内存保存，并自动添加到管理员写请求。
- 管理员写接口统一验证会话、角色、来源和 CSRF；公开留言、联系和问答提交保持原有行为。
- 退出接口保留幂等契约：无效会话返回 204；有效会话只有通过来源和 CSRF 校验后才吊销。
- 保留会话检查时清理过期内部记录的行为，没有修改 SQLite WAL 或连接初始化策略。

### 配置与部署假设

- 正式环境继续采用前端、`/api` 和 `/data/uploads` 同站部署，不支持独立 API 主域或跨站 Cookie。
- CORS 只在显式配置时开放 GET、POST、PUT、DELETE，以及 `Content-Type`、`X-CSRF-Token`。
- `APP_ENV=test` 同样必须显式提供测试可信来源，不使用隐式默认值。
- 当前仍假设没有不受信任的同站子域，登录限流和公开接口防滥用尚未完成。
