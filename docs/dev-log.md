## 2026-07-27：明确 Codex 对话与 Git 分支协作规则

### 实现内容

- 在项目 `AGENTS.md` 中增加对话、分支、worktree 和任务交接规则。
- 明确同一工作目录同时只能由一个对话修改代码。
- 明确小改动可以直接推进 `main`，涉及接口、数据、安全、依赖、存储或部署的改动应使用功能分支。
- 增加“新改动开始时只判断一次大小”的规则；同一改动执行期间不重复判断，除非需求范围发生实质扩大。

### 设计原因

- 多个 Codex 对话共享同一工作目录，普通 Git 分支不能隔离同时发生的文件修改。
- 用风险而不是对话数量决定是否创建分支，可以在保持简单工作流的同时保护稳定主线。
- 真正并行修改必须使用独立 worktree，并继续协调共享接口和高冲突文件。
- 改动大小判断属于当前对话的固定起始检查，无需额外创建 subagent。

### 验证结果

- 本轮只修改规则和开发日志，没有改变前端、后端或数据行为。
- 已检查新增规则与现有开发、验证和安全要求没有冲突。

### 遗留问题与下一步

- 仓库仍需要完成首次提交和远程推送。
- 当前只有一个工作目录，后续仍按“一次一个代码修改对话”执行。

- 默认使用同域 `/api` 与 `/data`，同时支持通过 Vite 环境变量配置独立域名。

- 新增 `VITE_API_BASE_URL`、`VITE_FILE_BASE_URL` 和 `DEV_PROXY_TARGET` 配置。

## 2026-07-28：管理员认证与管理接口权限闭环

### 实现内容

- 新增管理员登录、会话检查和退出接口，使用服务端内存会话、随机不透明 Token 和 `HttpOnly` Cookie。
- 服务端只保存 Token 的 SHA-256 摘要，并使用 `threading.RLock` 保护会话创建、验证、过期清理和吊销。
- 会话采用两小时绝对过期，不自动续期；Cookie 使用 `SameSite=Strict` 和 `Path=/api`，登录时不设置 `Max-Age` 或 `Expires`。
- 统一保护管理数据、问答与追问审核、删除、联系记录、课件上传和课件删除接口。
- 从 URL 查询参数和审核请求体中移除管理员密码；公开问答接口始终只返回已发布内容。
- 管理页面新增会话检查、登录、退出以及 401、403 和其他错误的分类处理，密码和 Token 不写入浏览器持久存储。
- 从公开留言页移除管理员密码弹窗和删除入口。
- 新增会话、Cookie、权限矩阵、公开数据隔离和启动配置验证测试。

### 配置与部署限制

- `APP_ENV` 必须显式设置为 `development`、`test` 或 `production`。
- `ADMIN_SESSION_TTL_SECONDS` 默认 7200 秒，只接受 300～28800 秒的整数。
- `ADMIN_PASSWORD` 不再使用默认值；production 中缺失、使用 `admin123` 或示例值、少于 12 个字符时拒绝启动。
- 当前内存会话只支持单实例、单进程后端，生产环境只能运行一个 Uvicorn worker。多进程或多实例前必须迁移到共享会话存储。
- 当前认证只支持前端与 API 同站部署，前端使用 `credentials: "same-origin"`；独立 API 域名和跨域 Cookie 留给后续 CORS 任务。

### 安全假设与边界

- 当前以 `SameSite=Strict` 作为单站场景的基础 CSRF 防护，假设没有不受信任的同站子域、Cookie 不设置宽泛 Domain，并且所有状态修改接口使用非 GET 方法。
- 公开上线前仍需完成精确 CORS 与可信 Origin、Origin/Referer 校验或 CSRF Token 等更完整防护。
- 登录限流、文件大小与 MIME 校验、对象存储和多管理员账号仍未处理。本轮完成不代表后台已经适合直接暴露到公网。
- 不记录原始密码、原始会话 Token 或完整 Cookie。

- 使用标准 Windows Python 3.13 确认项目现有后端依赖均已安装，无需新增或升级依赖。
- 后端 13 项测试全部通过，覆盖会话并发、绝对过期、伪造 Token、Cookie、登录退出、401/403、管理接口权限矩阵、公开数据隔离和启动配置校验。
